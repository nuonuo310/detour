# iPhone Shortcuts → Detour

Detour's GitHub Actions bridge is split into two write paths:

- `wake`, `music`, `food` use the event pipeline: raw `payload` → `tools/build-event.mjs` → `tools/append-event.mjs`.
- `date-plan`, `date-wish`, `date-memory` use the date mutation pipeline: raw `payload` → `tools/mutate-date.mjs`.

The iPhone Shortcut should stay thin: collect natural values, JSON-encode one payload, and dispatch the matching workflow. The phone must never edit `data/*.json` itself.

## Event workflow request

Use `.github/workflows/dry-run-detour-event.yml` for the first connection test, then switch only the workflow filename to `.github/workflows/append-detour-event.yml` for real writes.

```json
{
  "ref": "dev",
  "inputs": {
    "type": "music",
    "payload": "{...raw payload JSON as a string...}"
  }
}
```

Supported `type` values: `wake`, `music`, `food`.

Example music payload:

```json
{
  "song": "Song",
  "artist": "Artist",
  "link": "https://open.spotify.com/...",
  "message": "给糯糯。"
}
```

The repository normalizes aliases such as `song → title`, `link → url`, and `message → note`. The Shortcut does not need to build the final persistent event schema.

## Date workflow request

Use `.github/workflows/dry-run-date-mutation.yml` first, then switch only the workflow filename to `.github/workflows/mutate-detour-date.yml` for real writes.

```json
{
  "ref": "dev",
  "inputs": {
    "action": "date-wish",
    "payload": "{...raw date payload JSON as a string...}"
  }
}
```

Supported `action` values:

- `date-plan` — replace the single upcoming date plan.
- `date-wish` — append one place to the wish list.
- `date-memory` — append one completed date memory, optionally with photos.

Keep these as separate Shortcut actions/branches rather than pretending all date changes are one event type.

## Music flow

Useful raw fields: `song`, `artist`, `link`, `message`, optional `at`.

Dispatching the Detour record and opening/playing Spotify are separate outcomes. A Spotify or app-opening failure must not delete or undo a successfully logged Detour event.

## Food flow

Useful raw fields: `kind`, `name`, `store`, `reason`, `message`, optional `at`.

Current categories are `奶茶`, `外卖`, `零食`, `礼物`, `日用品`, `宠物用品`.

## Wake automation

Wake records use the same event bridge as music and food, but are generated by the wake mechanism instead of a manual Shortcut. Useful raw aliases include `choice`, `reason`, `message`, `tags`, optional `at`.

## Failure behavior

- Workflow dispatch failure: preserve the payload upstream so it can be retried.
- Duplicate event retry: safe; `append-event.mjs` ignores the same deterministic event ID.
- Duplicate date wish/memory retry: safe; `mutate-date.mjs` ignores the same stable mutation ID.
- Spotify/open-app failure: Detour logging may still succeed.
- GitHub Pages delay: expected; a data commit can exist before the public page refreshes.

## Security checkpoint

The authenticated GitHub request is configured only on the user's device. Never commit a personal access token, Authorization header, or other write credential to repository files, Pages JavaScript, screenshots, issues, or Shortcut documentation.

See `PHONE_SETUP_CHECKLIST.md` for the one-time device setup sequence and `event-templates.md` for copy-ready payload shapes.
